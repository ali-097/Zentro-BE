# Security Policy

## Reporting a vulnerability

**Please don't open a public issue.**

Report privately through GitHub's [Security Advisories](https://github.com/ali-097/zentro-be/security/advisories/new),
which creates a private thread with the maintainers.

Include what you can:

- What the issue is and roughly how severe you think it is
- Steps to reproduce, or a proof of concept
- Affected endpoints, files or versions
- Anything you think the fix should account for

You'll get an acknowledgement within a few days. This is a personal project without a
funded security team, so please be patient — but it will be taken seriously.

## Scope

Zentro holds a shared financial ledger between people who know each other. The findings that
matter most here:

- **Reading or modifying another user's or group's data.** Broken object-level authorization
  is this application's highest risk — see [docs/security.md](./docs/security.md).
- Authentication bypass, token forgery, session fixation, or refresh-token replay.
- SQL injection, or any query built from unvalidated input.
- Anything that lets one user alter another's balance.
- Secret or credential exposure.
- Account enumeration through timing or response differences.

Out of scope: missing hardening headers with no demonstrated impact, rate-limit findings on
endpoints already documented as unlimited, vulnerabilities in dependencies with no
exploitable path in this codebase, and reports generated by a scanner with no verification.

## Supported versions

The project is pre-release. Only `main` is supported.

## Disclosure

Please give us a reasonable window to ship a fix before publishing. Credit is offered in the
advisory unless you'd rather not be named.
